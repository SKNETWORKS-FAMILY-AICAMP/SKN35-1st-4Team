# 앗찻차! 프로젝트 계획안

SKN35 1차 프로젝트 · 4팀 (승희 · 치훈 · 종원 · 연주 · 은미)

## 1. 배경

- 서울 도심(종로구)은 주정차 단속이 잦은데, 운전자는 "여기 세워도 되는지"를
  현장 표지판 외에 확인할 방법이 없다
- 단속 이력·CCTV 위치·주차장 정보는 공공데이터로 각각 존재하지만 **흩어져 있어**
  실제 판단에 쓰기 어렵다
- 기존 지도 앱은 주차장 위치는 알려줘도 **"그 자리에 세우면 위험한지"** 는 알려주지 않는다

## 2. 목표와 컨셉

> **"앗, 여기 세우면 안 되는 곳이었네"를 3초 만에.**

흩어진 데이터 3종(주차장·단속 이력·CCTV)을 한 지도에 통합하고,
내 위치 기준 단속 위험을 판정해 **합법 주차장이라는 대안**과 함께 보여준다.

**컨셉 원칙 — 불법주정차를 유도하지 않는다.** "언제 단속을 피할 수 있나"가 아니라
"과태료 대신 주차장을 쓰면 얼마를 아끼나"를 말한다. 시간대 분석도
안전한 시간의 안내가 아니라 단속 빈도의 증거로만 제시한다.

## 3. 범위

| 구분 | 내용 |
|---|---|
| 지역 | 서울 종로구 (수집기는 `--district all`로 확장 가능) |
| 데이터 | 주차장 232곳 · 단속 이력 232,853건(2024.03~2025.12) · CCTV 196대 · FAQ 90건 · 민원 91건 |
| 기능 | 기능명세서 F-01 ~ F-11 (위험 판정 · 절약 배너 · 통합 지도 · 추천 · 회원/기록 · FAQ/민원) |
| 제외 | 실시간 단속 알림(데이터 없음), 결제, 네이티브 앱 |

## 5. 추진 단계

| 단계 | 내용 | 산출물 |
|---|---|---|
| 1. 데이터 탐색 | 후보 소스 실측 — OA-13122는 좌표 117/850뿐이라 폐기, parking.seoul.go.kr 크롤링으로 대체 결정 | 데이터 소스 평가표 (README) |
| 2. 수집·정제 | 담당자별 수집기 작성, 좌표·요금·운영시간 정규화 | `collectors/*`, `data/cleaned/*` |
| 3. DB 설계·적재 | 스키마 7테이블, 로컬 MySQL → TiDB Cloud 이전, 일괄 적재기 | `db/schema.sql`, `loaders/*` |
| 4. 핵심 기능 | 위험 판정·추천·지도 통합, 개별 페이지를 홈 레이어로 흡수 | `app_pages/home.py`, `common/*` |
| 5. 브랜드·UX | '앗찻차!' 브랜딩, 디자인 시스템, 컨트롤 단순화(20→12), 카드형 결과 | `common/ui.py`, `assets/*` |
| 6. 배포·안정화 | Streamlit Cloud + Secrets, https 지도 이슈 해결, 설정 진단 내장 | 배포 URL, [트러블슈팅](트러블슈팅.md) |
| 7. 문서화 | README·기능명세서·아키텍처·트러블슈팅 정리 | `docs/*` |

## 6. 기술 선택과 이유

| 선택 | 이유 |
|---|---|
| Streamlit | 팀 전원이 파이썬으로 화면까지. `st.navigation`으로 멀티페이지, CCv2로 GPS·드래그 같은 커스텀 상호작용 보완 |
| Kakao Maps | 국내 지도 정확도 + CustomOverlay·Polygon·Circle로 히트 블롭 표현 |
| TiDB Cloud Serverless | 무료 티어로 팀 공유 DB + 배포 앱 접속. MySQL 호환이라 로컬 MySQL과 코드 동일 |
| uv | 잠금 파일 기반 재현 가능한 환경. 배포용 requirements.txt는 런타임 전용으로 분리 |
| 크롤링(주차장) | 공공 CSV보다 좌표 100%·민영 포함·요금 상세 — 실측 후 결정 |

## 7. 리스크와 대응 (실제 발생 포함)

| 리스크 | 대응 |
|---|---|
| 공공데이터 품질 (좌표 결측, 요금 미공개) | 소스 실측 후 교체, 요금 미공개는 "정보 없음"으로 구분 표시 |
| 조용한 폴백이 장애를 은닉 | DB 설정 시 실패를 화면에 노출하는 정책으로 전환 |
| 외부 SDK 제약 (카카오 도메인·https) | 오류 안내 패널 내장, document.write 가로채기 |
| 배포 환경 차이 (.env 없음, 패키지 상이) | config가 Secrets 겸용, 설정 진단 화면, requirements 분리 |
| 팀 병합 충돌 (스키마·페이지 중복) | 테이블명 단일화(complain), 페이지 통합, 병합 후 즉시 동작 검증 |
| 비밀번호 노출 | 로테이션 + Secrets/.env 이중 관리, 코드·문서에 값 미기록 |

## 8. 기대 효과

- 운전자: 주차 전 3초 확인으로 과태료(최소 4만원) 예방, 근처 합법 주차장 즉시 안내
- 데이터: 단속 이력의 시간대·공간 패턴 시각화 → "어디가 왜 위험한지" 근거 제시
- 팀: 수집→정제→적재→서비스→배포 전 과정을 실데이터로 경험
